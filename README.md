# Учебная практика: Разработка информационных систем и баз данных

Данный репозиторий содержит выполнение практических заданий по проектированию баз данных, обработке данных, разработке ядра информационной системы, многооконной архитектуры и интеграции CRUD-операций.

## Структура репозитория

### Тема: Базы данных (07.09.2026)
- **`Задание 07.09/1 Вопрос/`**
  - `schema_bd.pdf` — Диаграмма спроектированной структуры базы данных (ER-диаграмма).
- **`Задание 07.09/2 Вопрос/`**
  - `schema.sql` — SQL-скрипт развертывания структуры базы данных (`CREATE TABLE`, `DROP TABLE`, первичные и внешние ключи, ограничения).
- **`Задание 07.09/3 вопрос/`**
  - `Задачи/` — Исходные файлы с аномалиями (`import_partners.csv`, `import_sales.txt`).
  - `cleaned_partners.csv`, `cleaned_products.csv`, `cleaned_deliveries.csv` — Очищенные от аномалий файлы данных.
  - `import_and_check.sql` — SQL-скрипт импорта данных и проверочные запросы `SELECT COUNT(*)`.
- **`Задание 07.09/4 вопрос/`**
  - `queries.sql` — SQL-скрипт с 3 бизнес-запросами для приложения (агрегация с `LEFT JOIN`, транзакция `BEGIN...COMMIT`, детальная история продаж за период).

### Тема: Ядро и базовый интерфейс (14.09.2026)
- **`Задание 14.09/Разработка ядра/`**
  - `discount.py` — Реализация функции расчета индивидуального процента скидки партнера (`calculate_partner_discount`).
  - `test_discount.py` — Модульные тесты (`unittest`) с проверкой всех граничных значений и 100% покрытием.
- **`Задание 14.09/Интеграция с БД/`**
  - `db_service.py` — Модуль подключения к БД через native-драйвер `psycopg2` (PostgreSQL), выполнение запроса агрегации (`SUM` + `LEFT JOIN` по `sales_history`) и функция `get_partner_with_discount`.
  - `test_db_service.py` — Модульные тесты проверки взаимодействия с БД, обработки отсутствующих продаж и расчета скидок.
  - `api.py` — REST API для асинхронного взаимодействия с клиентской частью (JavaScript).
- **`Задание 14.09/Разработка интерфейса (UI)/`**
  - `main_window.py` — Экранная форма (Tkinter) для просмотра списка партнеров со скидками в соответствии с макетом Screenshot_2.
  - `index.html`, `style.css` — Альтернативная веб-форма интерфейса со стилями и поддержкой асинхронной подгрузки данных.
  - `resources/` — Папка графических ресурсов (логотип `logo.png`, иконка приложения `icon.png`).
- **`Задание 14.09/Наполнение интерфейса и отладка/`**
  - `app.py` — Финальное приложение CRM со связкой UI и БД, автоматическим расчетом скидок, защитой от отсутствующих продаж и статус-баром.
  - `test_resilience.py` — Модульные тесты проверки отказоустойчивости (NULL-продажи, пустые контакты).
  - `demo_check.py` — Комплексный демонстрационный тест для проверки готовности проекта к сдаче.

### Тема: Многооконная архитектура и CRUD (21.09.2026)
- **`Учебная практика 21.09.2026/Проектирование многооконной архитектуры и навигации/`**
  - `main_window.py` — Главная форма (`MainWindow`, заголовок `"CRM: Реестр партнеров"`) с кнопкой «+ Добавить партнера».
  - `partner_edit_window.py` — Форма карточки партнера (`PartnerEditWindow`, заголовки `"CRM: Карточка партнера [Создание]"` и `"CRM: Карточка партнера [Редактирование]"`) с кнопкой «Назад» и сохранением состояния.
  - `test_navigation.py` — Модульные тесты навигации и заголовков окон.
- **`Учебная практика 21.09.2026/Разработка формы добавления и редактирования партнера/`**
  - `partner_edit_window.py` — Полноценная форма со всеми полями ТЗ (наименование, Combobox типа партнера, рейтинг, адрес, директор, телефон и email с плейсхолдерами).
  - `tooltips.py` — Компонент всплывающих подсказок (`ToolTip`).
  - `main_window.py` — Форма реестра с передачей данных между окнами.
  - `test_form.py` — Модульные тесты полей, подсказок и состояний формы.
- **`Учебная практика 21.09.2026/Интеграция формы с БД (CRUD-операции и обновление UI)/`**
  - `db_manager.py` — Модуль работы с БД, поддержка CRUD (`INSERT`, `UPDATE`), сохранение ссылочной целостности и транзакций.
  - `partner_edit_window.py` — Форма с автозаполнением данных из БД и сохранением.
  - `main_window.py` — Главный экран с автоматическим обновлением UI после изменений.
  - `test_crud.py` — Модульные тесты CRUD-операций и ссылочной целостности.
- **`Учебная практика 21.09.2026/Обработка исключений и интерактивные уведомления (UX-UI)/`**
  - `validators.py` — Модуль валидации (рейтинг int >= 0, обязательные поля, синтаксис email) и исключение `ValidationError`.
  - `dialogs.py` — Модуль системных диалоговых окон (`MessageBox` типов Error, Warning, Information с пиктограммами).
  - `partner_edit_window.py` — Форма с контролем несохраненных данных (предупреждение при «Назад»), валидацией и уведомлением об успехе.
  - `main_window.py` — Финальное приложение CRM с отказоустойчивостью при недоступности СУБД.
  - `test_error_handling.py` — Модульные тесты сценариев валидации и обработки исключений.

### Тема: История реализации, расчет материалов и аудит безопасности (28.09.2026)
- **`Учебная практика 28.09.2026/Разработка интерфейса истории реализации продукции/`**
  - `partner_history_window.py` — Окно `PartnerHistoryWindow` для просмотра истории отгрузок выбранного партнера (с фирменным стилем, логотипом, иконкой и человекочитаемыми датами).
  - `main_window.py` — Реестр партнеров с кнопкой «История продаж» и передачей `partner_id`.
  - `db_manager.py` — Менеджер базы данных с оптимизированным SQL JOIN (`deliveries` + `products`).
  - `test_history_window.py` — Модульные тесты выборки данных и связывания таблиц.
- **`Учебная практика 28.09.2026/Разработка ядра алгоритма расчета материалов/`**
  - `material_calculator.py` — Функция расчета необходимого сырья `calculate_material_requirement` с учетом коэффициентов, процента брака и округления `math.ceil`.
  - `db_manager.py` — Модуль доступа к справочникам типов продукции и сырья.
  - `test_material_calculator.py` — Модульные тесты расчета и обработки краевых условий.
- **`Учебная практика 28.09.2026/Интеграция метода расчета и комплексное тестирование/`**
  - `material_calculator_window.py` — Интерактивная форма калькулятора сырья с выпадающими списками и выводом результата на экран.
  - `main_window.py` — Главная форма CRM-системы со связкой всех окон.
  - `test_integration.py` — Комплексные тесты взаимодействия интерфейса и ядра с защитой от сбоев.
- **`Учебная практика 28.09.2026/Модульное тестирование (Unit Testing) и аудит безопасности/`**
  - `test_material_calculation.py` — Модульные тесты метода расчета сырья (5 обязательных тест-кейсов ТЗ: стандартный, округление ceil, несуществующий тип, отрицательные параметры, нулевое количество).
  - `test_security_audit.py` — Тесты аудита безопасности и защиты от SQL-инъекций.
  - `logger.py` — Регистратор событий с записью в файл `app.log`.
  - `SECURITY_AUDIT.md` — Аналитический отчет об аудите безопасности и протоколировании.
