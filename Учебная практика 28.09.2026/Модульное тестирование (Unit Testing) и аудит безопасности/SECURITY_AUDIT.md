# Отчет об аудите информационной безопасности и протоколировании ошибок

## 1. Цель аудита
Проверка программных компонентов CRM-системы на соответствие требованиям информационной безопасности перед сдачей подсистемы в промышленную эксплуатацию:
1. Защита от атак типа SQL-инъекция (SQL Injection, CWE-89);
2. Безопасность обработки пользовательского ввода в текстовых полях и диалоговых окнах;
3. Формирование отчетного журнала аудита (`app.log`) с обязательной фиксацией даты, времени и смыслового описания возникающих исключений.

---

## 2. Анализ уязвимостей SQL-инъекций (SQL Injection Prevention)

### Методология аудита
Были проанализированы все точки взаимодействия приложения с СУБД SQLite в модуле `db_manager.py`:
- `get_all_partners()` — выборка списка контрагентов и суммарных продаж;
- `get_partner_by_id(partner_id)` — получение реквизитов партнера по первичному ключу;
- `get_partner_sales_history(partner_id)` — выборка детальной истории отгрузок с объединением таблиц (`JOIN`);
- `search_partners_by_name(search_term)` — поиск и фильтрация организаций;
- `add_partner(data)` — добавление нового партнера (`INSERT`);
- `update_partner(partner_id, data)` — редактирование существующего контрагента (`UPDATE`);
- `get_product_type_coefficient(product_type_id)` — получение коэффициента типа продукции;
- `get_material_defect_rate(material_type_id)` — получение процента брака материала.

### Результаты анализа кода:
- **Конкатенация строк в SQL-запросах**: полностью отсутствует. Конструкции вида `f"... WHERE id = {user_id}"` или `"... WHERE name = '" + name + "'"` не используются ни в одном модуле.
- **Использование плейсхолдеров**: Все SQL-вызовы используют параметризованные подстановки через маркеры позиционных аргументов (`?`).
  Пример безопасного запроса:
  ```python
  cursor.execute(
      "SELECT id, company_name, email FROM partners WHERE company_name LIKE ? ORDER BY id ASC;",
      (f"%{search_term}%",)
  )
  ```
- **Экранирование спецсимволов**: Передача драйверу СУБД кортежа параметров гарантирует автоматическое экранирование кавычек (`'`, `"`), точек с запятой (`;`), комментариев (`--`, `/* */`) и управляющих последовательностей на бинарном уровне протокола СУБД.

### Результаты тест-кейсов (модуль `test_security_audit.py`):
1. **Тест внедрения логических тавтологий (`' OR '1'='1`)**:
   - Входное значение: `' OR '1'='1` в поисковый запрос.
   - Результат: СУБД выполняет буквальный поиск подстроки, не модифицируя синтаксическое дерево запроса. Возвращен корректный пустой список. Тест пройден.
2. **Тест внедрения составных деструктивных инструкций (Stacked Queries: `'; DROP TABLE partners; --`)**:
   - Входное значение: `Тестовая'; DROP TABLE partners; --` в поле наименования компании при `INSERT`.
   - Результат: Таблица сохранена без повреждений, значение записано в поле как единая строка. Целостность схемы данных не нарушена. Тест пройден.
3. **Тест манипуляции числовыми идентификаторами**:
   - Попытка внедрения недопустимых идентификаторов в `get_partner_by_id`.
   - Результат: Перехват исключения `PartnerNotFoundError` с корректной фиксацией в журнале без аварийного завершения процесса. Тест пройден.

## 3. Система протоколирования ошибок (Logging Audit)

### Архитектура модуля логирования (`logger.py`):
- Для протоколирования задействован стандартный механизм `logging`.
- Целевой файл журнала: `app.log`.
- Формат записи:
  `ГГГГ-ММ-ДД ЧЧ:ММ:СС [УРОВЕНЬ] Сообщение ошибки`
- Кодировка файла: `UTF-8`.
- При возникновении исключительных ситуаций в блоках `try...except`:
  - Записывается точная дата и время возникновения события;
  - Указывается класс возникшего исключения (например, `IntegrityError`, `DatabaseConnectionError`);
  - Формируется детальное описание скомпрометированного контекста (например, конфликтный адрес электронной почты или идентификатор записи).

### Пример записей из `app.log`:
```text
2026-10-03 15:19:40 [ERROR] Нарушение уникальности при добавлении партнера с Email 'unique_audit@domain.ru' | Ошибка: IntegrityError: UNIQUE constraint failed: partners.email
2026-10-03 15:19:40 [ERROR] Партнер с идентификатором #999999 не найден в базе данных.
```

## 4. Заключение аудита безопасности
Программный комплекс соответствует всем требованиям корпоративной безопасности:
- Прямые SQL-инъекции невозможны благодаря 100% параметризации запросов;
- Граничные и аномальные значения обрабатываются защищенно, не приводя к падению программы;
- Обеспечено прозрачное и информативное логирование инцидентов для администраторов системы.
