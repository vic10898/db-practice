# Инфраструктура данных и ETL (База данных в 3NF)

## Описание работы
Разработана реляционная схема базы данных в третьей нормальной форме (3NF), обеспечивающая ссылочную целостность и строгие ограничения целостности данных. Выполнен ETL-конвейер для очистки предоставленных сырых CSV-файлов, содержащих скрытые аномалии.

## Выполненные задачи
1. **Проектирование схемы (3NF)**:
   - Таблица `partners` — реквизиты партнеров (`partner_id`, `partner_name`, `partner_type`, `rating`, `address`, `director`, `phone`, `inn`, `email`).
   - Таблица `products` — номенклатура продукции (`product_id`, `product_name`, `product_type_id`, `price`).
   - Таблица `sales_history` — история реализации со ссылочной целостностью (`FOREIGN KEY` на `partners` и `products`).
   - Вспомогательные справочники `product_types` и `material_types` для нормализации расчетов.
2. **DDL-скрипт (`schema.sql`)**:
   - Ограничения `NOT NULL`, `CHECK` и `UNIQUE` для полей ИНН и Email.
   - Фиксированная точность цен (`DECIMAL(10, 2)`).
   - Правила внешних ключей: `ON DELETE CASCADE` для партнеров и `ON DELETE RESTRICT` для номенклатуры.
3. **ETL-конвейер (`etl_process.py`)**:
   - Чтение сырых CSV-файлов с автоматическим определением кодировки (исправление `CP1251` для товаров).
   - Удаление лишних концевых и повторяющихся пробелов (`TRIM`).
   - Нормализация разнородных форматов дат (`DD.MM.YYYY`, `YYYY/MM/DD`, `DD-MM-YYYY` и др.) к стандарту СУБД `ГГГГ-ММ-ДД`.
   - Исключение строки с битым внешним ключом (`partner_id = 999`), сохранение ссылочной целостности.
   - Экспорт очищенных файлов в каталог `cleaned_data/`.
4. **Проверочные запросы (`import_and_check.sql`)**:
   - Запросы контроля количества строк, проверки отсутствия пробелов и агрегации истории продаж.

## Запуск
```bash
python3 etl_process.py
```
